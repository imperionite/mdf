# V1.0.0 Change Log

## Purpose

This document records the principal changes between the approved [MS1 proposal](https://docs.google.com/document/d/159k5Q9VZ9QieaRSABpE8hMTOG7tINOPJh0Zd3LwD6xw/edit?usp=sharing) and the MDF mobile application's MS2 implementation. The changes focus on implementation refinements, data integrity, and usability while retaining the four core use cases established in MS1.

## Change Log

| No. | Area                         | Change from MS1 to MS2                                                                                                                   | Reason                                                                                                                                                 |
| --- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Navigation                   | Refined the screen navigation flow using explicit navigation routes and back-stack handling.                                             | To make movement between the existing prescription and purchase-related screens more consistent and maintainable.                                      |
| 2   | Prescription presentation    | Organized prescription information into list summaries and more detailed views.                                                          | To keep the prescription list concise while allowing users to access additional prescription and medicine information when needed.                     |
| 3   | Prescription validation      | Added safeguards against removing medicines with purchase records and reducing prescribed quantities below quantities already purchased. | To preserve consistency between prescription records and their associated purchase history.                                                            |
| 4   | Purchase history and pricing | Preserved the price recorded for each purchase independently of subsequent changes to the current medicine price.                        | To ensure that historical purchase costs remain accurate when medicine prices change.                                                                  |
| 5   | Local data persistence       | Refined Room database migration and seed-data handling during implementation.                                                            | To support database structure changes and reduce the risk of unintentionally replacing existing records.                                               |
| 6   | Insight Report               | Implemented a lightweight report using static data visualization and simple calculations based on available application data.            | To provide a concise overview of relevant information without introducing an advanced analytics subsystem or replacing any of the four core use cases. |
| 7   | User feedback                | Refined loading and navigation feedback during application operations.                                                                   | To make application state changes more apparent and improve feedback during screen transitions and data operations.                                    |

## Scope Preservation

The four core use cases from MS1 remain the foundation of the application:

1. Create Prescription Transaction
2. Record Purchase Batch
3. Review Purchase History
4. Update Medicine Price

The changes listed above are intended to refine the implementation of these use cases and support the usability and integrity of the application. The Insight Report is treated as a supporting visualization, not as a replacement for or modification of the four original use cases.
